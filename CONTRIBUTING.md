# Contributing

Read [the implementation decisions](docs/implementation.md) before changing calculations, publishing logic or the bilingual flow. Run the commands in the README before opening a pull request. Use fictional data in test cases. A change that affects a calculation should include an independently computed case and the expected order of rounding, deductions and payments. Provide English and Nepali labels together and check both at 390 and 1440 CSS pixels. Ask for native Nepali review for new financial copy.

For a new source, record its publisher, exact location, retrieval timestamp, effective interval, access rights and the fields it supports. Open a review candidate with the source difference and affected scenarios. Confirm redistribution rights before storing source documents in the repository.

Review changes to calculations, evidence and releases separately from visual changes. Enable the included CI workflow as a required branch check once the GitHub repository is linked. Assign real repository owners and reviewers before enabling CODEOWNERS or granting publication privileges. The maintainer should decide the code license and data license before making the repository public.
